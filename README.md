# Мой первый платформер

Маленькая 2D-игра на Phaser 3, TypeScript и Vite для совместных опытов с ребёнком. Пока есть прямоугольный герой, земля и платформы. Картинки и звуки не нужны.

## Запуск

1. Если Node.js ещё нет, скачайте **LTS-версию** с https://nodejs.org/ и установите её с обычными настройками. npm установится вместе с Node.js. После установки заново откройте терминал.
2. Откройте терминал в папке проекта и выполните:

   ```sh
   npm install
   npm run dev
   ```

3. Откройте в браузере адрес, который напишет Vite (обычно http://localhost:5173). Если клавиши не работают, щёлкните по игре.

Стрелки **← / →** — движение, **↑** — прыжок, **Space** — атака, **R** — начать уровень заново. Пока атака только проигрывает взмах мечом, без нанесения урона. Для остановки сервера нажмите **Ctrl+C** в терминале.

## Что менять сначала

Начните с `src/config.ts`: измените число, сохраните файл и посмотрите на результат в браузере.

- `PLAYER_SPEED` — скорость бега. Попробуйте 400 вместо 280.
- `PLAYER_JUMP_VELOCITY` — скорость прыжка вверх. Попробуйте -650 вместо -560.
- `GRAVITY` — сила тяжести. Попробуйте 900 вместо 1200.

В `src/scenes/Level1Scene.ts` можно менять положения и размеры платформ: `x` идёт вправо, `y` — вниз. Координаты обозначают центр прямоугольника.

## Где находится код

- `src/main.ts` — создание игры и включение Arcade Physics.
- `src/config.ts` — размер игры (1280×720) и настройки движения.
- `src/scenes/` — сцены: BootScene запускает Level1Scene; MenuScene — заготовка меню. Чтобы увидеть меню, замените `Level1Scene` на `MenuScene` в BootScene.
- `src/player/Player.ts` — прямоугольник героя, физическое тело, бег и прыжок.
- `src/objects/` — заготовки Collectible и Enemy; пока на уровне их нет.
- `public/assets/images/` — сюда кладите будущие PNG-картинки.
- `public/assets/sounds/` — сюда кладите звуки.
- `public/assets/tilemaps/` — сюда кладите карты уровней.

Добавление файла в assets само по себе не добавляет его в игру. Позже загрузку можно написать в методе `preload()` сцены BootScene, например: `this.load.image('hero', 'assets/images/hero.png')`. Начальный `/` в пути не нужен, чтобы игра работала в подпапке сайта.

## Проверка и сборка

```sh
npm run typecheck
npm run build
```

Первая команда проверяет TypeScript. Вторая повторяет проверку и собирает готовый сайт в `dist/`. Для просмотра сборки выполните `npm run preview` и откройте адрес из терминала.

Production-сборка настроена для адреса `/dinogame/`, а `npm run dev` по-прежнему открывает игру в корне локального сайта. Открывайте игру через сервер, а не двойным щелчком по HTML-файлу.

## Публикация на GitHub Pages

1. Создайте на GitHub репозиторий `dinogame` и отправьте файлы проекта в ветку `main`, включая `package-lock.json` и `.github/workflows/deploy.yml`. Папки `node_modules` и `dist` отправлять не нужно.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
3. Каждый push в `main` запускает публикацию. Если первый запуск был до включения Pages, откройте **Actions → Deploy to GitHub Pages → Run workflow** и выберите `main`.
4. Дождитесь успешного завершения workflow. Игра будет доступна по адресу `https://ВАШ-ЛОГИН.github.io/dinogame/`.

Workflow выполняет `npm ci`, затем `npm run build` и публикует содержимое `dist` официальными GitHub Actions. Дополнительные библиотеки и личные токены не нужны. Подробнее: [инструкция Vite для GitHub Pages](https://vite.dev/guide/static-deploy#github-pages).
